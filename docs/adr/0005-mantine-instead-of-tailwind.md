# Mantine instead of Tailwind and Base UI for the interface

The site's interface moves from Tailwind CSS utility classes plus one Base UI primitive to Mantine (`@mantine/core`). We switch for the same reason as in ADR 0001: Self-Engine is built with Mantine, so both of Gwydion's codebases now share one component library and one set of conventions. The portfolio should show how he builds apps, and Mantine also brings the app parts the shell still lacks, such as an app shell, navigation rows, drawers, menus, a command palette and notifications. Building those on Base UI and Tailwind would mean designing and styling each one ourselves.

What stays the site's own: the colour tokens in `src/styles/app.css` (`light-dark()` pairs that the contrast test checks), to which Mantine's colour variables point (`src/theme/mantine.ts`), and the theme store in `src/theme/theme.ts`. That store owns the storage key, the pre-paint script, the chrome colour and the favicon, and Mantine reads and writes it through a colour scheme manager. As in Self-Engine's theme package, the site's theme owns the state and Mantine follows it. Mantine's styles sit in their own cascade layer, so the site's CSS Modules win. Tailwind is removed entirely, so that two styling systems never live side by side.

The look lives in the theme first (`src/theme/components.ts`): each Mantine component gets its defaults, CSS variables and states there once, and Mantine's neutral palettes are warmed to the site's greys, so views only place components and the whole site looks alike. A view keeps a small CSS Module only for what is specific to that one place and that props can't express, such as a grid with media queries, a sticky rail or the tab bar's sliding indicator.
